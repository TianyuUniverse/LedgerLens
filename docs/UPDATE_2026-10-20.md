# 2026-10-20：分页、对话式录入与可玩的训练场

## 用户现在怎样操作

软件分成首页、账单明细、成长图鉴、目标冒险、分类记忆、储蓄计划和 AI 助手七个视图。侧栏、手机底部导航和页面选择器只显示所选视图；浏览器前进、后退和直接打开 `#assistant` 等链接都可使用。图表来源和 AI 方案按钮会切换到对应页面。切换视图不会清空当前对话或未确认的草稿。

记账、设立目标、安排预算、生成储蓄方案、记录目标存入／取回、填写复盘和确认分类用途，都默认打开小狐管家的对话窗口。用户先说想法，AI 追问缺少的必要信息，再显示草稿卡片。数字、日期、类型和金额范围由程序检查；用户可以继续改口，最后点击确认保存。原表单保留为“手动填写”备用入口。图表周期、分类筛选等查询控件仍可直接选择。

没有填写已有储蓄时，目标从零开始并在草稿中说明；目标日期为可选项。储蓄方案保留用户指定的固定开销和最低预算，预览后账单变化则要求重新计算。分类记忆不会在用户明确拒绝时自动启用。模型失败时明确提示本地整理，不冒充 AI 成功。

## 录入的技术边界

`ledger/setup_chat.py` 保存分模式、带版本号的草稿、历史消息和业务上下文。模型仅返回对话文本和字段补丁。服务端限制每种模式允许的字段，程序提取的明确数字优先；新消息和确认操作必须使用最新草稿版本。确认接口调用已有的目标、预算、账单、复盘和记忆服务，不给模型直接写库工具。

同一草稿的重复确认返回已保存的结果；目标与储蓄记录还使用已有的操作编号保证重试不会重复入账或领奖。真实金额使用整数分。AI 对话本身不授予经验。

AI 请求发送当前对话、草稿和必需的上下文；确认消费用途时也会发送该笔账单的描述、对方和备注。窗口有发送说明和 AI 开关。密钥只保留在本地私有配置，不进入浏览器、源码、GitHub 或压缩包。

## 游戏有了实际互动

“小狐的线索小岛”是每日三关的账单用途练习。用户点选线索答案，也可以按数字键选择、按方向键前进；角色随关卡移动。答错会提示查看用途线索，答对显示原因，完成有终点反馈。关卡使用合成账单，不能当作真实消费结论。

AI 可为这些情境编写连续探险引子。正确分类、关卡进度和奖励由程序验证。每日首次完成获得十五点装饰性经验，重新打开、提交旧关卡或重复完成不会重复领奖。关闭窗口后仍能继续当天的进度；本地情境可以升级为 AI 引子，保留已完成关卡。

修复了答对后方向键偶尔不响应的问题：重绘移除了旧按钮，导致键盘焦点落到对话框外。现在焦点移到“向前走一步”，奖励面板刷新也不阻塞移动。`scripts/setup_browser_check.cjs` 验证实际答题与方向键推进。

## 界面整理

- 黄白简约风格、统一按钮层级，鼠标点击不出现黄框；键盘操作保留清晰的中性焦点。
- 正文十六像素，说明与表单标签放大；手机和图表文字一起调整。
- 数字输入去掉步进箭头，金额、日期等字段按内容设置宽度。
- 滑条使用细轨道与圆形滑块；分类选中与目标选中状态去掉厚重描边。
- 删除页脚课程说明，操作处保留有实际作用的数据来源、保存状态和发送说明。

## 验证证据

当前自动测试共 **150 项**。五组隔离浏览器流程覆盖原有收支、记忆与方案、目标冒险、图鉴和新的七视图／七类对话／训练场。所有浏览器检查关闭模型并使用临时合成账本。

`live_setup_check.json` 记录七类对话共八次真实模型调用，第一次模糊目标会追问；当时的分类用途案例还需要继续补充。`live_setup_completion_check.json` 记录改进后的用途草稿及 AI 训练场两次真实调用，成功生成可确认的用途卡和 AI 引子，账本与经验不变。这些是合成集成案例，不是独立准确率评估，也不是用户研究。

可复现命令：

```powershell
python scripts/verify.py
node scripts/setup_browser_check.cjs
python scripts/check_shared_files.py
```

只有主动运行 `python scripts/live_setup_check.py` 或 `python scripts/live_setup_completion_check.py` 才会在开发检查中调用已配置模型，产生 API 用量。
