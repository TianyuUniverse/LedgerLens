# 微信原生账单导入与分类记忆整理

2026-10-20 当前版本。游戏展示已按用户要求撤下，储蓄目标和历史记录保留。

## 日常使用

1. 首页或账单明细页点击“导入微信 / CSV 账单”，直接选择微信解压后的原始 `.xlsx`。
2. 程序跳过导出说明、定位交易表头，显示交易笔数、新增、重复、单列项目和金额预览。此时不写账本。
3. 展开单列项目，核对退款或未完成交易；点击确认后才整批导入。取消不保存。
4. 进入“分类记忆 → 待确认账单”，选择一笔账单。对话上方会展示日期、金额、对方和备注。
5. 用自己的话说清用途，核对分类草稿，然后明确选择“仅改这笔”“记住，每次确认”或“记住，自动分类”。选择方式也只是修改草稿，最后仍需确认保存。
6. “已记住的规则”显示用途、分类、匹配条件、自动处理方式、来源及实际自动识别笔数，可搜索、修改和停用。删除有单独确认。

收款方条件是完全相同，描述和备注条件是包含关键词；条件需要同时符合。对方相同不等于用途相同。自动分类需要能区分用途的描述或备注，仅凭收款方仍需确认。记忆是个人确认的匹配规则，AI 用于理解用途及整理草稿，并未训练个人模型。

## 微信导入的计算口径

- 支持微信交易表头“交易时间、交易类型、交易对方、商品、收/支、金额(元)、当前状态、交易单号、备注”，兼容前置说明、共享字符串、内联字符串、Excel 数值日期和数值金额。
- 微信标为支出的转账保留为支出，再按实际用途分类；明确的零钱提现、零钱通内部划转等不计收入或消费。
- 已全额退款、对方退还、取消和失败记录单列。退款到账行不计为新的收入；部分退款的原支出按剩余金额导入。预览可核对每一行的排除原因。
- 若之前已经导入的交易后来发生金额或退款状态变化，预览会列出冲突账单编号，并阻止自动覆盖。跨期退款还没有独立的退款账务模型，需核对对应原支出；不要把本功能当银行余额核对工具。
- 使用微信交易单号去重，避免把同日同商户的两笔相同金额消费合并。来源时间、状态、单号单独保留，不塞进记忆关键词。人工修改分类后重新导入仍识别为同一笔。
- 金额转为整数分。先完整校验，再在数据库事务中保存；无效文件或行不会导致半批数据落库。

只支持解压后的 `.xlsx`，不支持加密压缩包、旧 `.xls`、图片和支付宝原生导出。单文件最多 5 MB、5,000 笔。读取 OOXML 值，不执行公式、宏、外部链接；限制解压体积与表数量。解析在本地完成，不调用 AI。

## 修复原因与验证

原记忆页只有总数和示例按钮，没有可选择的待确认清单；保存后还会跳到账单页。对话修改旧记忆时，从交易行重新初始化草稿，丢失已批准的条件和自动设置。本次把已保存的记忆作为编辑草稿来源，并保留版本检查；新增明确的处理方式按钮、保存结果反馈和来源卡片。原手动表单仍是备用入口。

游戏主地图原为进度展示，没有地图点击或自由移动；角色只在跨越里程碑时换位置。用户要求先撤下游戏，当前版本移除地图、练习、经验、徽章、等级和奖励弹窗的全部页面入口。`#adventure` 旧地址转到普通储蓄目标页；既有数据和后端兼容代码未删除。目标创建、存入、取回、归档、恢复与储蓄轨迹继续可用。

验证记录：

- `python scripts/verify.py`：168 项自动测试通过；历史规则样例 18/20、限定查账 9/9，均不是独立准确率评估。
- 五组浏览器检查：`browser_check.cjs`、`workflow_browser_check.cjs`、`reports_browser_check.cjs`、`setup_browser_check.cjs`、`workspace_browser_check.cjs`。覆盖对话、条件保留、未来复用、导入预览/取消/确认/重复、旧链接兼容、储蓄操作、图表及 390px 布局，全部使用临时合成账本。
- `python scripts/live_memory_check.py`：显式调用两次真实 DeepSeek，在合成账本上检查用途理解及编辑保留条件，并验证确认后的后续导入。不代表用户研究或泛化准确率。

新增的公开截图及测试样例均为合成数据。原始私人账单、私人数据库和 API 配置不放入 Git 或项目压缩包。
